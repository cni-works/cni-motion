# 0. Codexへの最重要指示

本書を **CNI Motion v1.0の唯一の実装仕様** とする。

以前作成した仕様書・旧CSS・旧JavaScriptを前提にせず、本書に基づいて新規設計すること。

旧実装の以下のような方式は移植しない。

```text
.slide-up1
.slide-up2
.slide-up3
.anm
.v
.active
.appear
.fadeout
#splash
.splashbg1
.splashbg2
```

旧実装とのクラス互換性は不要。

また以下は禁止する。

* jQuery
* window scrollごとの全DOM走査
* 汎用的な `.active` `.visible` `.appear` 等のクラス
* 外部Animation Libraryへの必須依存
* Lightning固有実装
* CNI Blocksへの必須依存
* JavaScript失敗時にコンテンツが永久に非表示になる設計
* Loaderが永久に残る設計
* Otterのコード・CSS・名称体系のコピー

Otterは機能要求の参考であり、CNI Motionは独自実装とする。

# 2. CNI Motionの目的

CNI MotionはWordPress Gutenberg / Block Editorを対象とした「サイトモーション統合管理プラグイン」とする。

従来、サイト制作のたびにSimple Custom CSS and JS等へ記述していた、

* Fade
* Slide
* Zoom
* Blur
* Reveal
* Mask Reveal
* Stagger
* Bounce
* Swing
* Tada
* Jello
* Flip
* Page Loader
* Hero / First View

などをGUIから設定可能にする。

目標は単なるスクロールアニメーションプラグインではない。

> **WordPressサイトの「動き」を、ブロック・First View・Loaderまで一元管理するMotion Toolkit**

とする。

---

# 3. 既存ワークフローを置き換える目標

CNI Motion v1は以下の作業を可能な限り不要にする。

### Simple Custom CSS and JS

サイトごとにアニメーションCSS / JSをコピーする作業。

### Otter Animations

現在Otterを利用している理由のうち、少なくとも以下のMotion用途をCNI Motionで代替する。

* Bouncing
* Fading
* Zooming
* Flipping
* Jello
* Tada
* Swing
* Delay
* Speed
* Hover Trigger
* Trigger Offset
* Editor Replay

Otter全機能の互換プラグインを目指すものではない。

# 4. CNIシリーズ内での位置付け

CNI Motionは独立プラグインとする。

```text
CNI
│
├─ CNI Blocks
│  └─ 独自ブロック集
│
├─ My Block Launcher
│  └─ よく使うブロック呼び出し
│
└─ CNI Motion
   └─ ブロック・ページ・LoaderのMotion
```

以下は必須依存にしない。

```text
CNI Blocks
Lightning
Lightning Child Theme
Otter
```

CNI Blocksが存在する場合のみIntegrationを有効化する。

# 19. CNI MotionのMotionデザイン原則

CNI Motionは派手さより実制作での使いやすさを優先する。

特にFade系について、

> **標準状態では移動距離を小さくする。**

長距離から飛び込んでくるFadeを標準にしない。

# 48. Mask Reveal実装方針

可能な限り擬似要素を利用する。

不要なWrapperを保存HTMLへ追加しない。

ただしテーマの擬似要素と衝突する可能性が高いブロックには無条件で提供しない。

安全なBlock Allow Listを持つ。

v1推奨：

```text
core/image
core/group
core/cover
core/media-text
CNI Container系
```

テキストにはClip Revealを優先する。

# 49. Effect Definition Registry

Effectをswitch文へ大量に直書きしない。

Effect Registryとして一元定義する。

概念例：

```js
{
    slug: 'fade-up',
    category: 'entrance',
    label: 'フェードアップ',

    defaultDuration: 600,
    defaultEasing: 'ease-out',

    supports: {
        distance: true,
        blur: false,
        maskColor: false
    },

    triggers: [
        'auto',
        'site-ready',
        'scroll',
        'immediate'
    ],

    reducedMotionFallback: 'fade'
}
```

---

# 50. Emphasis Registry例

```js
    slug: 'tada',

    triggers: [
        'auto',

        'scroll',
        'hover',
        'immediate'

    reducedMotionFallback: 'none'
}
```

Effect追加時にMotion Engine全体を書き換えないこと。

# 55. Auto Trigger

デフォルト。

基本判定：

```text
ページ初期表示領域内
↓
Site Ready

初期表示領域外
↓
Scroll
```

Heroをユーザーが意識せずSite Readyで発火できるようにする。

---

# 56. Auto判定タイミング

レイアウトが確定する前に位置判定しない。

Site Ready準備処理後に、

```text
getBoundingClientRect()
```

等で初期位置を判定する。

---

# 57. Site Ready

Hero / First View用Trigger。

共通イベント：

```js
document.dispatchEvent(
    new CustomEvent('cni:site-ready')
);
```

---

# 58. Site Ready発火条件

ページにつき **必ず1回だけ**。

以下すべてで成立すること。

```text
Loaderあり
Loaderなし
Loader Skip
Loaderエラー
Storageエラー
Loader最大待機Timeout
```

# 66. Hover Replay

Hover Triggerは基本的に再Hover可能。

Motion実行中に連続発火して状態が破綻しないよう、

```text
running中の再発火を無視
```

または安全にrestartする。

v1は「実行中は無視」でよい。

# 196. Otterとの共存

CNI MotionはOtterを自動停止・変更しない。

両方が有効でもPlugin Errorを起こさない。

ただし同一Blockに複数Animation Systemを重ねた場合のTransform競合は保証しない。

v1ではOtter Animationの自動移行は実装しない。

# 234. Codexは既存ファイルを最初に調査する

```text
構成確認
```

とする。

# 239. 旧挙動の重要参考値

コードそのものではなく以下のみ仕様値として維持する。

### Classic Slide

```text
Direction Motion
20px前後
600ms
```

ただしCNI標準Fade Directionは16pxへ改善する。

### Blur Zoom旧挙動

```text
Blur 5px
Scale 1.2
800ms
```

CNI標準はScale 1.12。

Strong設定で1.2を再現可能。

### Classic Loader

```text
Logo Hold      700ms
Logo Fade      400ms
Split          500ms
White BG
```

# 240. Acceptance Criteria

CNI Motion v1.0は以下を満たした場合に完成とする。

### A

Simple Custom CSS and JSへFade / Slide / Blur Zoom / Loaderコードを書かなくても同等用途を実現できる。

### B

Otterをアニメーション目的だけで使用していた主要用途、

```text
Fade
Bounce
Zoom
Flip
Jello
Tada
Swing
Delay
Speed
Hover
Offset
Replay
```

をCNI Motionで代替できる。

### C

HeroがLoader裏で先にアニメーション終了しない。

### D

Loaderの表示頻度を、

```text
毎回
セッション1回
初回訪問のみ
```

から選択できる。

### E

ロゴがなくても、

```text
Site Title
Custom Text
Line
Dots
None
```

でLoaderが成立する。

### F

JSが壊れても本文が読める。

### G

Loaderが壊れてもサイトへ入れる。

### H

Mobile Delayを簡単に無効化できる。

### I

Group等で子要素をStagger表示できる。

### J

Reduced Motionを尊重する。

# 241. CNI Motionの最終コンセプト

CNI Motionは「Animationをたくさん持つPlugin」で終わらせない。

目指すもの：

> **制作現場で繰り返し使う“動き”を、コードを書かず、派手すぎず、サイトごとに細かく調整できるWordPress Motion System**

とする。

特に、

```text
Fade Inを使いやすく
移動距離は控えめ
SpeedとDelayは独立
PresetとCustomを両立
HeroとLoaderを正しく連携
Revealを実用的に
Staggerで連番Classを不要に
Emphasis Motionも利用可能
MobileとAccessibilityを最初から考慮
```

をCNI Motion固有の設計方針とする。

---

# 242. 最終優先順位

実装判断に迷った場合は、以下の順番で優先する。

```text
1. コンテンツが確実に表示される
2. WordPressを壊さない
3. 操作が簡単
4. 実制作で使いやすい
5. Performance
6. Accessibility
7. 見た目の派手さ
8. Effect数
```

Effect数を増やすために品質を落としてはならない。
